## 언제 어떤 에이전트를 사용할까?

### 기획자 (`planner`)
- 프로젝트 시작 시 전체 계획을 세울 때
- 새로운 기능을 추가하기 전 기획/명세가 필요할 때
- 사이트맵이나 사용자 흐름을 설계할 때
- 경쟁 사이트를 분석/벤치마킹할 때
- MVP 범위를 정하거나 우선순위를 조정할 때

### 아키텍트 (`architect`)
- 프로젝트 폴더 구조를 설계할 때
- 데이터 흐름이나 컴포넌트 계층을 결정할 때
- 기술 선택(라이브러리, 서비스)을 비교할 때
- 코드 구조를 리뷰하고 개선 방향을 잡을 때
- 성능 병목을 진단할 때

### UI/UX 디자이너 (`designer`)
- 페이지 레이아웃을 구상할 때
- 색상, 폰트, 디자인 시스템을 결정할 때
- 매물 카드, 검색 UI 등의 디자인 방향을 잡을 때
- 다른 부동산 사이트를 참고/분석할 때
- 반응형 디자인 전략을 세울 때
- 접근성 기준 확인이 필요할 때

### 프론트엔드 개발자 (`frontend-dev`)
- 새로운 페이지나 컴포넌트를 만들 때
- React/Next.js 코드를 작성하거나 수정할 때
- Tailwind CSS 스타일링 작업을 할 때
- 반응형 레이아웃을 구현할 때
- 코드에서 에러가 나서 도움이 필요할 때

### 백엔드 개발자 (`backend-dev`)
- API Route를 만들거나 수정할 때
- Supabase 데이터베이스 테이블을 설계/수정할 때
- 매물 검색/필터 쿼리를 작성할 때
- 문의 폼 등 서버 로직이 필요할 때
- 인증/인가, RLS 정책을 설정할 때
- 이미지 업로드 등 스토리지 연동이 필요할 때

### SEO 전문가 (`seo-specialist`)
- 메타태그, OG 태그를 최적화할 때
- sitemap.xml, robots.txt를 설정할 때
- 매물 페이지의 구조화된 데이터(JSON-LD)를 작성할 때
- 검색 노출 전략을 세울 때
- 네이버 SEO 최적화가 필요할 때

### QA & 보안 감사관 (`qa-security`)
- 기능 구현 후 테스트가 필요할 때
- 배포 전 전체 점검이 필요할 때
- 보안 취약점을 스캔하고 싶을 때
- 코드 품질(타입 에러, 미사용 코드 등)을 점검할 때
- 성능 지표를 측정하고 싶을 때

## 에이전트 협업 흐름

### 새 프로젝트 시작
```
1. planner     → 프로젝트 기획, 사이트맵, 기능 명세
2. architect   → 기술 구조 설계, 폴더 구조
3. designer    → 디자인 시스템, 페이지 레이아웃
4. backend-dev → DB 스키마, API 설계 및 구현
5. frontend-dev → UI 컴포넌트 및 페이지 구현
6. seo-specialist → SEO 설정
7. qa-security → 전체 점검 및 보안 감사
```

### 새 기능 추가
```
1. planner     → 기능 명세 작성
2. designer    → UI 디자인 방향
3. backend-dev → 필요한 API/DB 작업
4. frontend-dev → UI 구현
5. qa-security → 기능 테스트 + 보안 점검
```

### 버그 수정
```
1. qa-security → 버그 원인 분석
2. frontend-dev 또는 backend-dev → 수정
3. qa-security → 수정 확인 + 회귀 테스트
```
